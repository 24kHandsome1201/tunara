# Tunara 界面、功能与流程审查

日期：2026-08-08

## 结论

Tunara 的产品方向依然清楚：终端是工作主体，侧栏承载项目与会话，右侧区域承载检查和辅助工具。当前的混乱主要来自功能增长之后，导航归属和信息层级没有同步调整。

最明显的问题出现在右侧检查器。默认宽度约 320 px，却把十个入口放在同一层，同时混入当前会话、传输连接、仓库或主机、全局配置等多种作用域。用户需要先扫描标签，再判断功能归属和生效范围。

## 设计规则

1. 每类对象保留一个稳定主入口。
2. 高频操作常驻，低频工具渐进展开，管理能力集中收纳。
3. 同一种状态尽量只在一个区域持续展示。
4. 作用域只在影响理解和操作安全时强调。
5. 命令面板继续作为全部能力的兜底入口。

## 本分支已经实现

分支：`ux/simplify-inspector-navigation`

1. 检查器常驻入口收敛为 Overview、Changes、Files。
2. Preview、Notes、Transfers、Metadata、Forwarding、Diagnostics、Known Hosts 收入更多工具菜单。
3. 选中低频工具后，当前工具以临时选中标签显示，用户仍能确认所在位置。
4. Metadata 仅在有效 SSH 连接绑定存在时出现，Forwarding 仅对远程会话出现。
5. 仓库来源信息只在 Changes 中显示，减少其他页面的重复上下文。
6. 新增导航模型测试，并更新检查器交互测试。

## 建议的主流程

1. 新建本地会话或 SSH 会话。
2. 在终端中完成主要工作。
3. 使用 Changes、Files 或 Preview 检查结果。
4. 通过外部编辑器或 Git 工具完成提交和推送。

这条流程与 Tunara 的只读 Review Rail 定位一致，也能避免产品逐步变成另一个 IDE 或代理控制台。

## 下一轮建议

### 1. 稳定标题栏职责

侧栏可见时，侧栏负责会话切换，标题栏只显示临时文件。侧栏隐藏时，终端标签恢复，保证会话仍可切换。这样可以消除打开首个文件后，标题栏突然出现全部终端会话的布局跳变。

### 2. 建立 Connections 中心

把 SSH Profiles、Known Hosts、端口转发和连接诊断集中到一个 Connections 区域。会话中的恢复提示和端口转发入口可以跳转过去，并自动带入当前连接。

### 3. 精简 Overview 首屏

首屏保留状态、Agent、改动和恢复操作。吉祥物、worktree、最近命令、时间线和低频动作进入折叠区，减少每次打开 Overview 时的阅读量。

### 4. Agent 区改成注意事项优先

优先展示等待确认、失败、需要恢复的会话。普通运行状态已经出现在会话卡片上，可以减少重复展示。

## 验收标准

1. 默认 320 px 检查器宽度下，三个主要入口无需横向滚动。
2. Changes 和 Files 保持一次点击可达。
3. 所有现有检查器能力在两次操作内可达。
4. 本地会话不展示无效的 SSH 连接工具。
5. 键盘标签导航和菜单焦点返回保持可用。
6. 切换低频工具时，当前页面名称保持可见。

## 验证状态

新增和修改的 TypeScript、TSX 文件已完成语法解析检查。导航能力过滤已有纯逻辑测试，检查器交互测试已经同步更新。完整的 `pnpm typecheck` 和 `pnpm test:ui` 尚未在本次连接环境中运行，需要在安装依赖的完整仓库中执行。
