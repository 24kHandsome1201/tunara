# Tunara 全量功能盘点与取舍

撰写日期：2026-08-18。对照当前源码（2.0.1），不是发版承诺。

本文回答三件事：

1. **现在有哪些用户可见功能**
2. **哪些功能对用户的成本高于价值**，适合删除、降级或收口
3. **主路径上缺什么、哪里值得优化**

产品原则仍以 [GOAL.md](./GOAL.md) 为准：terminal-first，不替代 shell / Git / 浏览器 / 编辑器 / Agent。右侧栏页签级取舍见已落地的 [INSPECTOR_PANELS.md](./INSPECTOR_PANELS.md)。用户可见能力与代码入口见 [FEATURES.md](./FEATURES.md)。

---

## 0. 结论（先看这个）

Tunara 的主线已经清楚：**真实终端 + 按目录分组的会话 + 只读 Git review + 有边界的文件/SSH**。价值高、该守住的是这四块。

当前的主要问题不是“功能不够”，而是 **壳层能力铺得比主线宽**：Preview、Agent 生命周期、Notebook/表格预览，各自都能讲出场景，但叠在一起会让新用户迷路，也把回归面撑得很大。本地使用日志、会话吉祥物、广播输入、starter 模板、会话笔记、固定概览页、自定义工作流模板、Quick Select，以及 Amp / Gemini / Copilot / Droid / Pi / Auggie / Devin / Aider 的基础识别已删除。

建议按三条线收敛，而不是再开新阶段：

| 动作 | 对象 | 理由 |
|------|------|------|
| **守住** | 终端、侧栏、Changes、Files 轻编辑、SSH 连接/SFTP/传输 | 这是每天打开 Dock 的理由 |
| **收口表面，保留内核** | Preview、Agent 识别、端口转发、命令面板 | 能力有用，入口和周边控件过重 |
| **已删除** | 使用日志、吉祥物、广播输入、starter、会话笔记、固定概览页、SSH 实时指标、Preview 截图/遥测回传/视口控制 | 维护与认知成本高于大多数用户的收益 |

## 1. 用户到底在干什么

一条完整但透明的路径（GOAL 原文）：进入 repository/worktree → 恢复终端 → 读或轻改文件 → 看绑定的 Preview → 审阅真实 diff → 用户自己决定 Git 操作。

拆成四条高频任务：

```
A. 本地多项目终端
   打开目录 → 跑命令/Agent → 切会话 → 看谁在跑、谁要确认

B. Agent 辅助改代码
   在项目目录开终端 → 启动 Claude/Codex 等 → 等待确认 → 看 Changes → 自己 commit

C. SSH 远程排查/修文件
   连主机 → 远程壳 → 浏览/传文件 → 轻改 → 看远程 Git → 断线重连

D. 看前端效果
   终端里出现 localhost URL → 打开 Preview → 刷新或在系统浏览器打开
```

后面的取舍都按这四条任务打分，而不是按“这个功能酷不酷”。

## 3. 成本高于价值：建议删除、降级或冻结

“成本”同时算 **用户认知**（入口、选项、误触）和 **工程回归**（代码量、测试矩阵、安全合同）。价值只按第 1 节四条任务打分。

### 3.1 建议降级（不要再投入，能藏就藏）

| 功能 | 用户价值 | 成本信号 | 建议 |
|------|----------|----------|------|
| **CLI 页对 4 个 Agent 预检** | 只有装了对应 CLI 的人才有用 | 每次打开设置都扫 PATH；未安装项全是“未找到” | 只展示本机已解析到的；未安装折叠成一行 |
| **行内图片** | 看 SIXEL/IIP 的人很少 | xterm Image addon；已可关 | 维持可选，不要默认开新格式 |
| **只读 Notebook** | Jupyter 用户偶发 | 塞进已经 1490 行的 `FilePreview.tsx` | 冻结能力，不要做执行/富输出 |

### 3.2 建议收口（能力留，表面砍）

这些不该删，但现在的 **表面积 > 收益**。

**Preview（最大的工程税）**

- 后端合同仍严格（来源键、generation、tunnel nonce、WKWebView ACL）。
- 对任务 D 有真实价值，但页签藏在「更多」，检测了 URL 也没有“要不要打开 Preview？”的轻提示。
- 身份 ID 与状态轮询对“看一下 localhost:5173”仍然偏重。
- **已收口：** 面板只保留 URL / 开 / 刷新 / 关 / 外开浏览器、导航、重启和显式 SSH tunnel；缩放、视口、截图、遥测已删除。

**4 种一等公民 Agent**

- 识别用一份 JSON。产品只承诺 Claude Code、Codex、Cursor、OpenCode。
- 真正贵的是 **hooks + 等待确认 + 安全 resume + TUI 兼容矩阵**（GOAL_STATUS 里大段证据都在这）。Claude / Codex 是主路径。
- **已收口：** Amp、Gemini、Copilot、Droid、Pi、Auggie、Devin、Aider 不再做基础命令识别或品牌角标。resume / hooks / 等待确认只承诺这四个一等公民。

**设置 6 个页签**

- 代码当前是：外观、终端、无障碍、快捷键、SSH、高级；CLI 排障、更新和传输上限已收进高级。
- 无障碍页几乎只有读屏开关 + macOS 隐私跳转，不值得单独占一个 tab。
- **继续观察：** 若页签仍显拥挤，再把无障碍并入外观或终端；CLI 未安装项默认折叠。

**命令块筛选**

- 块导航（上一条/下一条）值得留。
- 文本/正则/大小写/反选/上下文行更接近独立 log 工具。
- **收口：** 默认只留导航和简单过滤；高级筛选不要出现在空闲终端顶上。

**端口转发**

- 本地转发和动态 SOCKS 对 SSH 开发有用。
- 反向 RemoteForward 场景窄，还要限制回环。
- **收口：** 默认表单只暴露本地转发；另外两类放“更多类型”。不要再加第四种。

### 3.3 不建议删（即使代码很大）

| 功能 | 为什么留下 |
|------|------------|
| 终端 / 分栏 / 粘贴保护 / 快照 | 产品存在的理由 |
| 侧栏分组、动态条、选目录新建 | 对 iTerm 用户的差异化 |
| 只读 Git Changes | 卖点；写操作继续不做 |
| Files + 安全写 + 工作区标签 | 远程修文件闭环的一半 |
| SSH 连接、SFTP、传输 journal | 远程闭环的另一半 |
| Agent 识别 + 等待确认 + 安全 resume（第一档） | 任务 B 的核心辅助 |
| 命令面板 | 键盘用户的总入口 |
| 纯净模式 | 成本低，对“终端要全屏”有用 |

## 4. 使用流程：缺什么、哪里摩擦大

### 4.1 第一次打开 / 每天开工（任务 A）

**现在：** 无会话时空状态有三个按钮：新建终端、选择目录、SSH。侧栏有主机快捷入口。最近目录主要在 ⌘K。重启后会恢复上次会话。

**摩擦**

1. **最近项目不够显眼。** `recentDirs` 已经持久化，空状态和侧栏却不展示。用户要先会用命令面板，或再选一次目录。
2. **新建终端默认 cwd 不透明。** “新建终端”落到哪（home？上次目录？）空状态没有说明。选目录才是更符合 workspace-first 的主按钮，视觉上却是次按钮。
3. **没有 shell integration 引导。** 命令块、cwd 跟随、部分 Agent 状态依赖 OSC 7/133。用户装完如果提示符没配，会觉得“侧栏目录不准、命令块没有”，但不知道缺的是 shell 配置。
4. **搜索有四套。** 侧栏会话搜、命令面板、终端 ⌘F、Files 搜/grep。没有“我要找什么”的分流提示，但也不该做成万能搜索框——缺的是命令面板里对这三类的明确分组文案。

**值得做**

- 空状态列出最近 3～5 个本地目录（数据已有）。
- 把「选择目录新建」提升为与「新建终端」同级或主 CTA。
- 若补 shell integration 引导，应放在命令块自身的空状态，不再增加固定概览页。

### 4.2 Agent 辅助改代码（任务 B）

**现在：** 用户自己在终端打 `claude` / `codex` → 角标出现 → 等待确认走动态条 → 改完后自己去 Changes 看 diff → 自己在终端 commit。Resume 只填入不执行。这与 GOAL 一致。

**摩擦**

1. **Agent 跑完后的 review 入口必须保持直接。** 当前动态条已在 Agent idle 且 Git dirty 时提供「查看改动」；不要再绕经固定概览页。
2. **Review 之后的 Git 写是故意缺口。** 正确。缺的是轻衔接：例如「在终端填入 `git status` / `git diff`」而不是内置 commit UI。
3. **恢复按钮的语义只承诺四个一等公民。** 其它 CLI 按普通终端进程处理，不再显示品牌识别或“可恢复”。
4. **CLI 路径覆盖是排障能力。** 它已收进设置 → 高级，不应让新用户误以为 Tunara 必须先配置 Agent 才能用。

**值得做**

- 保持动态条在 Agent 从 running → idle 且 Git dirty 时提供「查看改动」，不要增加第二条 review 路径。
- Resume 文案区分“已验证恢复”和“仅识别”。
- CLI 页改成排障页，不要让人觉得是必配项。

**不要做：** Agent 启动器、自动把命令写入 PTY、stage/commit。

### 4.3 SSH 远程修文件（任务 C）

**现在：** 连接对话框（profile / config 导入 / 四种认证）→ 远程壳 → Files 浏览、跟随 cwd、收藏路径、上传下载 → 轻编辑安全写 → 远程 Changes → 断线后动态条重连。手敲系统 `ssh` 会建议改用内置客户端。这是路线图说的“远程修复闭环”，主路径已经齐。

**摩擦**

1. **连接 UI 偏表单。** 有保存的 profile 时，仍容易先看到一排认证字段。高频应是：点主机 → 用上次认证偏好连上。
2. **传输进度曾经藏在「更多」。** Files 工具条已有进行中入口（Inspector 盘点已记）。保持这个入口，不要在 Files 里再做一套完整进度 UI。
3. **重连后 cwd / 转发 / 文件草稿** 对用户是黑盒。失败时终端退出提示有 remediation，但成功重连很少告诉“转发已按快照恢复、文件草稿还在”。
4. **反向转发、诊断报告、known_hosts** 对修一个远端文件不是主路径。known_hosts 已到设置，诊断报告只在失败路径按需出现，方向对。

**值得做**

- 连接对话框在有 profile 时默认“主机列表优先”，表单放“新主机”。
- 重连成功用一条短 Toast：cwd、转发条数、未保存草稿（有则提）。
- 本地 Files 没有“最近目录”下拉（SSH 已有收藏/最近路径）。本地会话可用 `recentDirs` 做同样的跳转。

**缺口（仍符合 GOAL）**

- 不能在 UI 里 commit。用“填入 git 命令”衔接即可。
- 不支持 ProxyCommand / Jump 多跳（现仅单跳 ProxyJump）。多跳是真实缺口，但实现贵，不要为少数用户先做。
- 把本地路径拖进 **本地** 终端变成路径插入：现在拖放主要服务 SSH 上传。本地“拖文件得路径”是终端本职，值得补。

### 4.4 看前端 Preview（任务 D）

**现在：** 终端输出里的 localhost URL 被收成 `previewSources` → 用户必须打开检查器 → 「更多」→ Preview → 再点打开。SSH 还要再开 tunnel。不扫端口、不自动起服务，正确。

**这是当前最大的流程缺口：** 能力做得很完整，**发现路径几乎断开**。用户更可能 ⌘-click 链接用系统浏览器，Preview 的 workspace 绑定因此很难发挥价值。

**值得做**

1. 新检测到来源时，终端顶或动态条给一次性「在 Preview 打开」，可忽略。
2. Preview 在用户打开后才会进入自动跟随；检测到来源时仍只给一次性入口。

### 4.5 文件：检查器 vs 主区标签

**现在：** Files 里打开文件会变成与终端并列的工作区标签（1.17.0）。检查器仍停在 Files。纯净模式可只留 Files。

**摩擦**

- 同一文件在右侧预览和主区标签之间职责重叠。用户会问：编辑发生在哪？
- 主区标签和会话标签挤在同一条 Titlebar（Titlebar 已超过 1000 行），窄窗时先丢的是可发现性。侧栏已按设备分组后，标题栏仍把全部终端和跨设备文件平铺，本地 `/tmp/a.txt` 与远端 `/tmp/a.txt` 看起来一样。
- 从 Diff 展开文件不能直接变成工作区标签（只能外部编辑器）。Review → 打开这个文件 是自然下一步。

**值得做**

- 明确规则并写在 UI 上：检查器 = 浏览/搜索；主区标签 = 阅读/轻编辑。
- Changes 文件行增加「在工作区打开」（受 256 KiB 边界限制）。
- 标题栏收成当前设备工作面：侧栏打开时只显示该设备文件；SSH 标签用来源与 ARIA 区分传输。见 [TITLEBAR_DEVICE_TABS.md](./TITLEBAR_DEVICE_TABS.md)。

### 4.6 检查器信息架构（与已落地盘点对齐）

已砍：固定概览、会话笔记、元数据与诊断独立 tab；已知主机移出右侧栏。还值得盯的：

| 点 | 状态 | 下一步 |
|----|------|--------|
| Changes 跳转 | 已可用 | Agent 完成后动态条/终端条可打开 Changes |
| Files → 传输入口 | 已落地 | 保持 |
| Preview 发现性 | 已落地 | 一次性入口；用户打开后自动跟随才选 Preview；WebView 仍需用户点打开 |
| 检查器视图快捷入口 | ⌘K 已覆盖 | Changes / Files / Preview / Transfers / Forwarding |

### 4.7 明确不要用“缺失”当借口加回去的

这些在 GOAL 里写死，流程上会感觉缺，但补上会变成另一个产品：

- 内置 AI 聊天 / 启动 Agent
- Diff 里 stage / commit / push
- 持久 Agent 历史搜索
- 插件市场、云 workspace
- 无限分栏、完整 IDE 编辑器、调试器

## 5. 建议落地顺序（按侵入性，不是按日历）

只改产品形状，不自动开新里程碑。

1. **发现性（已落地）**
   - 空状态最近目录；关光会话不再偷偷新建 `~`
   - Preview 来源一次性入口；用户打开后自动跟随才选 Preview
   - Agent idle 且 dirty 时「查看改动」
   - 命令面板可打开改动 / 文件 / Preview / 传输 / 转发
   - 选择目录新建是空状态主 CTA
   - 本地拖文件插入路径
   - shell integration 说明只在相关命令块空状态按需出现
2. **设置与叙事收口（中改）**
   - 无障碍并入外观
   - CLI 只展示已安装
   - 文档区分第一档 / 仅识别 Agent
3. **Preview 表面收口（已完成，不动安全内核）**
   - 已删除截图、遥测回传、缩放与设备视口
   - 有来源时提升入口，而不是继续藏在「更多」
4. **冻结周边（决策，几乎不写代码）**
   - Notebook：不再加功能
5. **大件拆分（工程，用户无感）**
   - `FilePreview.tsx` / `FileExplorer.tsx` / `Titlebar.tsx` 继续按模块切，避免再往单文件堆格式

不建议下一阶段先做：多跳 SSH、Preview 自动扫端口、更多 Agent 的产品级 resume。
